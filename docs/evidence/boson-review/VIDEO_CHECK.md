# YSH 윤곽선 영상 확인

2026-09-08 · 런타임 `cca5acf18df70555ffefb0f5d0dc37ebf4564953`

## 판단

[별도 추천 결론: Balanced · 출력 2픽셀](RECOMMENDATION.md)에 선택 이유와 적용 방법,
실제 장비에서 확인할 조건을 정리했다.

**이번 모니터용 640×480 출력에서는 balanced + 2픽셀을 우선 시험할 만하다.**
1픽셀보다 눈에 잘 띄면서 기존 팽창 3 커널 출력에 비해 화면을 가리는 면적이 작다.
이는 시각 검토 의견이며 안경 가독성 평가나 장애물 정확도 검증이 아니다.
런타임의 기본 설정은 이번 확인만으로 바꾸지 않았다.

천장·바닥의 짧은 선, 먼 구조물의 연결은 프레임 사이에 변한다. 특히 1.3→1.4초와
3.1→3.2초 구간에서 선이 이어지거나 떨어지는 변화가 확인된다. sparse는 선을 더 적게
그리지만 필요한 약한 경계도 생략할 수 있다. 선 굵기 개선과 시간 안정성 해결은 구별해야 한다.

## 사용한 영상

1. **합성 전 농연 열화상 표시 영상**: 저장소에 이미 있는 SmokeBasement run5 발췌 영상,
   `smoke_heldout_original.mp4`, 320×240, 10fps, 120프레임, 12초.
   원 데이터에서 리사이즈·시간 재표본화·인코딩한 표시 영상이며 Y16/온도 원시 데이터가 아니다.
   SHA256 `3bb826c914c96572ad796664a3e1941dff09803523f63671229f615a546f3aa2`.
2. **첨부 `boson_test.mp4`**: 320×256, 9fps, 90프레임, 10초. 이미 초록선이 합성된 영상이다.
   이전에 만든 원본 HUD/세선화 표시 비교를 함께 제공한다. 새 TEED를 이 합성 영상에
   다시 적용하지 않았으며, 원본 열 분포나 상세도 검출 평가에 사용하지 않는다.

## 비교 조건과 실측

농연 영상 전체 120프레임에 현재 TEED 체크포인트를 실행했다. 모든 방식은 프레임마다
같은 확률맵을 공유한다. 입력 320×240, CLAHE 2.0, 배경 .24, 최종 출력 640×480.
픽셀 굵기는 확대 전 모델 해상도가 아니라 이 출력 해상도를 기준으로 한다.
시간 평균·추가 학습·고온 후보 검출은 적용하지 않았다.

| 방식 | 평균 초록선 점유율 | 전체 경계가 비어 있는 프레임 |
|---|---:|---:|
| legacy (.75 threshold / 팽창 커널 3) | 11.50% | 0 / 120 |
| detailed / 1픽셀 | 1.27% | 0 / 120 |
| balanced / 1픽셀 | 1.18% | 0 / 120 |
| balanced / 2픽셀 | 2.63% | 0 / 120 |
| sparse / 1픽셀 | 1.03% | 0 / 120 |

어떤 프레임에서도 전체 경계가 비지 않았다는 사실은 개별 장애물 미검출이 없다는 뜻이 아니다.
열화상 소스의 빨간 후보 표시 픽셀은 모든 방식에서 0이었다.

원본·각 설정 5종·6분할 비교, 총 **MP4 7개 모두 120프레임/10fps로 끝까지 재디코드**했다.
출력 해상도는 단독 영상 640×480, 비교 영상 1920×1016이다.
비교 패널 순서는 위: 원본 / legacy / detailed1px,
아래: balanced1px / balanced2px / sparse1px이다.

초 단위 타임라인과 0/6/11.9초 비교 프레임을 검토했다. 원 영상에서 계산한 optical flow로
직전의 1픽셀 모델 경계를 정렬하고, 1픽셀 허용오차 밖에 남는 차이도 살폈다.
119쌍이 유효했으며 mean residual은 detailed 15.56%, balanced 14.73%, sparse 13.33%였다.
평균 flow 유효 픽셀 비율은 98.34%였다. 이는 카메라 움직임·가림·장면 변화·flow 오차를 포함한
진단값이며 **순수 깜빡임 비율이나 정확도 순위가 아니다**. 적은 선을 그리면 수치도 낮아질 수 있다.
변화량이 큰 1.4초·3.2초 주변의 인접 프레임을 추가 검토했다.

## 영상 위치와 재현

로컬 출력: `experiments/boson_review/outputs/video_check/`

- `comparison.mp4`: 원본과 다섯 설정의 동기화 비교.
- `balanced_2px.mp4`: 우선 검토할 단독 영상. 자막/새 패널 없음.
- `balanced_1px.mp4`, `detailed_1px.mp4`, `sparse_1px.mp4`, `legacy.mp4`: 각 설정 단독 영상.
- `original.mp4`: 같은 출력 크기로 맞춘 원본 표시 영상.
- `timeline.png`, `temporal_detail.png`, `entry_detail.png`: 시간 변화 검토 자료.
- `video_verification.json`: 프레임별 통계, 파일 SHA256, 전체 디코드 결과.
- `SOURCE_CREDITS.txt`: 원 출처와 처리 내용. 영상을 전달할 때 함께 보존한다.

첨부 Boson의 표시 굵기 비교는 로컬 `outputs/current_audit/comparison.mp4`에 있다.
해당 파일은 기존 합성 선을 추출해 세선화한 표시 실험이며 원본 열화상 복원이 아니다.

저장소 루트의 분석용 환경에서:

```bash
python experiments/boson_review/verify_video.py --output experiments/boson_review/outputs/video_check
```

의존성은 Orin 런타임의 torch/numpy/OpenCV contrib와 분석용 imageio-ffmpeg다.
원본의 출처 정보는 기존 SOURCE_CREDITS (원본 프로젝트 참조: `../obstacle_edges/deliverables/SOURCE_CREDITS.txt`; 선별본에는 미포함)에 있다.
GitHub에는 재현 코드·요약 JSON·대표 비교 프레임을 기록한다. MP4는 로컬에 보존한다.

## 범위

이번 확인으로 출력 영상 생성·프레임 연속성·설정별 표시 차이는 확인했다.
