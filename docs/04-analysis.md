# 4. 분석과 후속 연구

## 4.1 연구 의도가 어떻게 구체화되었나

처음에는 열화상 신호를 받아 눈으로 확인하고 “공간적으로 보여줄 수 있는가”를 탐색했다. 밝기를 z축으로 옮기는 방식은 데이터 구조와 시각화 연결을 빨리 시험하는 데 도움이 되었지만, 실제 거리를 만들지는 못했다. 다음 단계의 핵심은 깊이 복원보다, 농연 환경의 벽·문틀·장애물 경계를 덜 가리고 더 알아보기 쉽게 표시하는 문제로 좁혀졌다.

TEED/PiDiNet 비교와 작은 adaptation은 “더 복잡한 모델 또는 추가 학습이 지금 필요한가”를 판단하는 실험이었다. 기록상 파인튜닝의 뚜렷한 우월성은 없었고 PiDiNet은 해당 CPU에서 무거웠다. 그래서 기존 TEED를 유지하고 경계 선별과 표시를 분리하는 방향이 먼저 선택되었다.

거리별 폭 실험은 한 단계 더 나아가 “어떤 선이 더 가까운지 표시하자”는 UI 가설을 검증했다. 처음의 임의 1/2/3px 시연에서 1m/5px~8m/1px의 명확한 입력 계약, 연속 curve, stale/invalid 처리, 지속 FPS로 구체화되었다. 이 발전은 **renderer와 시스템 검증의 진전**이며, 거리 센서 자체가 붙었다는 뜻은 아니다.

## 4.2 현재 결론을 뒷받침하는 근거

| 판단 | 근거의 강도 | 범위 |
|---|---|---|
| grayscale을 PLY로 저장한 계산은 일관됨 | 강함: 전체 vertex 재검산 | 지정된 입력·수식·sampling의 구현 일치 |
| 굵은 선의 배경 가림을 줄였음 | 강함: 저장 mask/영상·점유율 | 화면 표시 밀도 |
| Balanced 2px가 모니터에서 유용한 후보 | 제한적: 시각 검토 | 해당 출력 해상도·장면의 표시 판단 |
| fusion-head 학습이 실제 수행됨 | 기록 근거 있음: steps/loss/변경 tensor/hash | 제한적 의사 라벨 adaptation |

| 실제 meter 또는 ℃를 정확히 측정 | 미검증 | 센서·보정·GT 필요 |
| 농연의 새 현장으로 일반화 | 미검증 | 다른 장소·센서·연기 조건 test 필요 |

## 4.3 숫자를 과대해석하기 쉬운 지점

**점유율 감소와 검출 품질:** 선을 없애면 점유율은 내려간다. 필요한 얇은 장애물을 잃어도 같은 방향으로 좋아 보일 수 있다. 모델 채택에는 선 면적뿐 아니라 장애물 boundary recall, 단차/호스 누락, 통행 공간 판단을 함께 봐야 한다.

**거친/가는 선의 시간 residual:** 두꺼운 선은 작은 이동에 더 관대하다. 다른 선 폭끼리 XOR/union이나 flow 잔차를 직접 비교하면 형상과 픽셀 허용오차가 결론을 바꾼다. residual에 장면 변화와 flow 오차가 섞인 점도 구분해야 한다.

**학습 loss와 새로운 능력:** self-generated pseudo label은 원 모델의 강약을 재배치할 수 있지만 원래 몰랐던 회피 의미를 정답처럼 보장하지 않는다. loss가 줄었다는 사실과 실제 위험 경계 recall이 늘었다는 주장은 다르다.

**영상 FPS와 센서 지연:** 10fps로 인코딩된 영상은 10fps 실시간 추론의 증거가 아니다. PC 30fps 처리도 센서 노출에서 안경 발광까지의 지연을 대신하지 않는다. 현재 측정 구간과 포함/제외 항목을 유지해야 한다.

**출력 1px의 의미:** 고정 320×240에서 1px가 다른 크기로 확대되면 물리적인 보이는 굵기도 달라진다. 실제 안경의 angular size·렌즈·색 대비·밝기·사용자 시력과 함께 평가해야 한다. 거리 결측 시 1px는 “안전하게 멀다”는 판정이 아니다.

**thermal intensity와 기하·온도:** AGC, 표면 방사율, 반사·주변 조건 등과 무관하게 밝기 하나를 meter나 ℃로 이름 바꾸면 안 된다. 현 코드에는 그 변환을 식별할 측정 모델과 calibration이 없다.

## 4.4 다음 실험의 우선순위

### A. 입력과 센서 계약을 먼저 고정한다

실제 part number, serial, 영상 encoding/bit depth, AGC/FFC 상태, timestamp 기준, 해상도·FPS, 카메라 intrinsics/왜곡을 함께 기록한다. HUD 합성 전 영상과 표시 영상을 따로 저장한다. radiometric 장치인 경우에만 제조사의 변환·보정 계약에 맞춘 temperature 경로를 별도로 검증한다.

거리 센서는 아직 미정이다. radar든 depth/LiDAR든 사용할 경우에는 미터 단위와 좌표계, timestamp, camera-to-sensor extrinsics, 등록 해상도, 유효 거리/품질을 함께 저장해야 한다. rosbag은 메시지를 재생할 수 있게 하지만 자동으로 시간 동기화나 공간 보정을 해결하지 않는다.

### B. 검출과 표시의 평가를 분리한다

동일한 probability/mask에서 출력 폭만 바꿔 표시 비교를 수행한다. 모델 비교에서는 최종 선 폭과 배경 scale을 고정하고, 수작업 boundary 정답에 맞춘 threshold 또는 precision/recall 곡선을 사용한다. 멀리 있는 가는 장애물, 호스, 단차, 문 개구부, 무장애 빈 장면을 포함한다.

같은 지하실의 다른 frame만 나누는 대신 현장/세션/장치 단위로 train-validation-test를 나눈다. 연기 조건의 직접 측정이 없으면 정량 농연 단계라고 이름 붙이지 말고 촬영 조건의 불확실성을 기록한다.

### C. 거리 대응 실패를 독립 시험한다

정지한 표적의 알려진 거리와 실제 센서값을 함께 수집하고, 가까운 물체가 먼 배경을 가리는 경계, 시야 밖, 드문 radar point, 다중반사, 누락, 늦은 sample, time reset을 따로 시험한다. 대응되지 않은 선에 임의로 “가까움/멀음”을 붙이지 않는 정책을 사용자에게 명확하게 표시해야 한다.

renderer의 단조성·노이즈 응답은 현재 합성 시험을 회귀 검증으로 유지하되, 실제 거리 정확도·pixel registration 오차와는 별도의 표에 보고한다. 수학적으로 부드러운 폭이 실제 장면에서도 안정적인지 movement와 occlusion에서 확인한다.

### D. 목표 보드와 실제 디스플레이에서 반복 검증한다

Jetson/카메라/센서/안경이 연결된 상태에서 180초 이상 동일 기준으로 측정하고, 열 스로틀링·전원·buffer·drop·재연결을 기록한다. GPU 완료·화면 표시·저장·최종 flush를 포함한 지표와 제외한 지표를 분리한다. 센서 노출→표시 지연은 host timestamp만으로 모두 알 수 없으므로 별도의 관측 수단이 필요하다.

마지막 채택 기준은 선이 적어 보이는지 하나가 아니라, 필요한 경계 누락률, 사용자의 통행 판단/반응시간, 시야 가림, 실제 장비의 tail latency다. 현재 자료는 그 시험을 설계할 출발점이며 현장 안전 효능을 입증한 제품 시험은 아니다.

## 4.5 재현성에서 먼저 보강할 것

1. 초기 52장 입력에 촬영 시각·장치·설정·장면 노트를 연결한다. 추측으로 과거 metadata를 채우지 않는다.
2. 원 실험의 Git commit, checkpoint hash, preprocessing, display resolution과 threshold를 하나의 manifest로 묶는다.
3. 부분 복사 코드와 팀 원본의 관계를 명시하고, 정확한 환경·외부 의존성·라이선스를 확보한 상태에서 재실행한다.
4. 공개 dataset의 인용과 resize/resampling/overlay 변환 사실을 유지한다. raw/HUD/합성 거리의 출처를 결과 영상에도 표시한다.
5. README의 요약 수치를 CSV/JSON에서 자동으로 생성하여 보고서와 실제 결과가 갈라지는 것을 줄인다.
