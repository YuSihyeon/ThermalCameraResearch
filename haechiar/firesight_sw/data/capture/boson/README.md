# Boson 320 raw 촬영 도구

FLIR Boson 320(비방사형, 9Hz, USB)에서 **16-bit raw 프레임을 변환 없이** TIFF로 저장하는
Windows용 녹화·점검 도구다. TEED 파인튜닝·평가용 열화상 데이터를 모으는 데 쓴다.
촬영 기록과 결과는 [`data/collection/`](../../collection/README.md)에 있다.

## 왜 이 방식인가

- OpenCV DirectShow로는 `Y16`이 적용되지 않아 8-bit AGC 영상(640×512)만 나온다.
  **flirpy `Boson.grab()`** 은 uint16 `(256, 320)` raw를 그대로 준다 → 이 경로로 수집한다.
  `astype` 등으로 강제 변환하지 않고, 녹화 시작 전에 uint16·shape·값 범위를 확인한다.
- 녹화 중 자동 FFC가 끼면 영상이 약 350 ms 멈추므로, 시리얼(COM)로 **FFC를 수동 모드**로 바꾸고
  녹화 직전에 1회만 실행한다. 대신 녹화 중 값이 천천히 드리프트하므로 분석은 장면 안의 상대값으로 한다.
- 실측 **8.57 fps** (프레임 간격 116.7 ms), TIFF 1장 164,096바이트 (5분 ≈ 0.43GB, 15분 ≈ 1.27GB).

## 설치

```powershell
py -3.12 -m pip install -r requirements.txt
```

Boson을 USB로 연결하면 영상 장치 "FLIR Video"와 시리얼 포트(예: COM3)가 잡힌다.
포트가 다르면 환경변수 `BOSON_PORT`로 지정한다.

## 사용법

1. 촬영 폴더를 만들고 `촬영시작.bat.example`을 `촬영시작.bat`으로 복사해 경로를 고친다.
   이 bat이 있는 폴더가 촬영 폴더(`BOSON_SHOOT_DIR`)가 된다.
2. 촬영 폴더에 `촬영순서.csv`를 둔다 (예: `data/collection/2026-10-14_2차/촬영순서.csv`).
   열: 순서, 코드, 유형, 세트, 높이, 카메라, 대상·열원, 조명, 이벤트(S), 최대(분), 계획 시각, 계획 메모
3. `촬영시작.bat` 실행 → 아직 안 찍은 다음 구도 자동 선택 → 콘솔에서 최대 녹화 시간(Enter = 순서표 값)
   → 미리보기 창 클릭 → **Enter** (FFC → 2초 후 녹화)

| 키 | 동작 |
| --- | --- |
| Enter | FFC 1회 → 녹화 시작 |
| S | EVENT 기록. T 구도: 긴 비프에 S(히터 치우러 들어가기 직전) → 치우고 나와서 S |
| Q | 녹화 중 두 번 누르면 종료 (READY에서는 한 번) |
| N | (READY) 이 구도 건너뛰기 |
| + / − | (READY) 최대 녹화 시간 1분씩 조정 |

- 코드가 `TEST`로 시작하면 `연습\`에, 그 외는 `sessions\<코드>\`에 저장한다.
- 코드가 `M`으로 시작하면 이동 촬영으로 보고 카메라 움직임 검사를 끈다.
- 이벤트(S)=예인 구도는 녹화 20초에 신호음(5초 전부터 카운트다운)을 낸다.
- 녹화 중에는 Windows 절전·화면 꺼짐을 막는다 (노트북 덮개를 닫으면 절전되므로 닫지 않는다).

## 저장 형식 (`sessions\<코드>\`)

| 파일 | 내용 |
| --- | --- |
| `frames/000000.tif …` | 16-bit raw 프레임 (카메라 값 그대로) |
| `timestamps.csv` | frame, elapsed_s, unix_time |
| `frozen_frames.csv` | 직전 프레임과 완전히 같은 프레임 (영상 정지) |
| `motion.csv` | 0.5초마다 기준 화면 대비 이동량·신뢰도 (고정 구도) |
| `meta.json` | 구도 정보, EVENT, 라벨 구간, 카메라 움직임, FFC, 프레임 수 |

`meta.json`의 라벨 구간 (T 구도):

| 필드 | 구간 |
| --- | --- |
| `clear` / `clear_ref` | 녹화 시작 ~ 첫 S 직전 / 그 마지막 10초 (히터가 프레임에 있을 수 있음) |
| `hot_ref` | 두 번째 S + 2초부터 10초 (히터·사람이 빠진 직후, 가장 뜨거운 깨끗한 구간) |
| `event_frame` / `event_end_frame` | 첫 S / 두 번째 S. 그 사이는 사람·히터가 움직이는 구간 |
| `camera_motion` | 움직임 구간, `aligned_until_frame`(처음부터 정렬이 보장되는 마지막 프레임) |
| `trimmed` | `trim_session.py`로 뒷부분을 잘라낸 경우 그 정보 |

## 카메라 움직임 감지

녹화 3~5초 평균 화면을 기준으로 0.5초마다 위상상관으로 비교한다. 2px 넘게 밀리면 경고하고
낮은 비프 2번을 낸다. T 구도의 신호 5초 전 ~ 두 번째 S 후 3초는 검사를 쉰다.
히터처럼 아주 뜨거운 부분은 비교에서 잘라내고(밝기 1~97% 범위), 장면이 바뀌어 신뢰도만 낮은 경우
(이동량 1.2px 이하)는 움직임으로 보지 않는다.

## 점검·정리 도구

| 명령 | 용도 |
| --- | --- |
| `py -3.12 check_sessions.py [코드 …]` | 프레임 수·간격·중복·uint16·EVENT·카메라 움직임 점검 |
| `py -3.12 check_sessions.py --align H00 H01 …` | 녹화 사이 카메라 위치 비교 (라벨 공유 전, 1px 이하면 같은 위치) |
| `py -3.12 fill_log.py` | `현장로그.csv`의 녹화 시작·S 시점·유효·자동 메모 채우기 (사람이 쓴 칸은 유지) |
| `py -3.12 trim_session.py <코드> <마지막 프레임> "<이유>"` | 카메라가 밀린 뒤 프레임을 잘라 `재촬영_보관\`으로 옮김 |
| `py -3.12 live_view.py` | 구도 확인용 라이브 뷰 (저장 안 함, 녹화와 동시 실행 금지) |
| `py -3.12 pack_for_drive.py <촬영 폴더> <출력 폴더> <이름>` | 원본 보관용으로 녹화별 zip 생성 + 검증 + `MANIFEST.csv`(SHA-256) |

## 알려진 점

- OpenCV 5의 `cv2.phaseCorrelate`는 입력 배열을 덮어쓰므로 기준 화면은 복사본을 넘긴다.
- Boson 펌웨어가 FFC 완료 상태를 보고하지 않아, FFC 완료는 "1초 대기 + 중복 프레임 종료"로 판정한다.
- 콘솔·미리보기 안내는 한국어(맑은 고딕)이며 Windows 전용(`winsound`)이다.
