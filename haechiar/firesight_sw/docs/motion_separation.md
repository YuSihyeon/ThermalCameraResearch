# 정적·동적 윤곽 분리

카메라 움직임을 보정한 뒤 윤곽의 잔여 움직임을 기준으로 표시 정책을 나눈다. 사람·벽을 인식하는 객체 분류기가 아니라 광류 기반 움직임 추정이다. TEED 가중치와 원본 열화상 고온 색상 보존 경로는 변경하지 않는다.

## 동작

- 카메라 이동·회전에 대응하는 공통 변환을 추정한다. 온도 눈금·로고를 제외하고, 정합 신뢰도와 영상 여러 위치의 지지를 확인한다.
- 정합이 확실한 정적 영역은 TEED 확률 단계부터 과거 비중 0.8(30fps 기준)로 안정화한다. 새 강한 경계는 즉시 반영하고 현재 확률 근거가 사라진 경계는 누적하지 않는다.
- 공통 변환과 일치하는 윤곽이 연속 관측되면 정적으로 추정하고 더 강하게 위치를 안정화한다. 선이 만나는 분기점도 같은 좌표를 공유하도록 한다.
- 카메라 움직임과 다른 윤곽은 동적으로 추정하며 현재 관측을 빠르게 반영한다. 분류가 불확실하거나 공통 변환 추정이 실패하면 기존 정책으로 돌아간다.
- 정적 윤곽도 현재 영상의 근거가 남아 있을 때만 짧게 표시를 유지한다. 실제로 사라졌거나 가려진 선, 바뀐 연결 구조를 이전 모양으로 장기 고정하지 않는다.
- 원본 노랑·주황·빨강, 빨간 고온 영역 외곽선, 고온 영역 위의 초록 선 제거는 기존 처리를 유지한다. 이 변경의 안정화 대상은 TEED 구조물 윤곽이다.

## 실행

저장소 루트에서:

```sh
python edge/orin/run_pipeline.py --source "../data/fire360/raw/IFSI Video 10 (2).mp4" --device cpu --motion-separated-edges --thermal-palette-overlay --profiles edge/teed/profiles/fire360_video_profiles.json --display-width 720 --display-height 405 --pace
```

`--motion-separated-edges`는 윤곽 추적을 함께 켠다. 기존 방식 비교는 이 옵션 대신 `--contour-edges`를 사용한다. `--legacy-edges`는 두 후처리를 모두 끈다. 기본값은 기존 방식을 보존한다.

## 검증 원칙

같은 TEED 확률 입력에서 전후 결과를 비교한다. 영상 움직임으로 정렬한 경계 변화율, 출력 초록 선의 밝기·위치 변화, 작은 윤곽 개수 변동과 기존 경계 근방 보존을 함께 확인한다. 선을 제거한 효과를 안정화로 오해하지 않도록 경계 유지 비율도 기록한다.

합성 검사는 카메라 이동, 독립적으로 움직이는 피사체, 정지 선의 좌표 떨림, 선의 합류 지점, 가림·소멸, 정합 실패 및 재생 불연속을 구분한다. 이 지표들은 화면 안정성 검사이며, 실제 장애물 회피 정확도나 사람/배경 분류 정답률을 뜻하지 않는다.

TEED가 매 프레임 다른 연결 구조를 만드는 현상이나 불·연기 자체의 변화까지 완전히 제거할 수는 없다. 원근 변화가 크거나 움직이는 피사체가 화면 대부분을 차지하면 배경 움직임 추정이 불확실해질 수 있다. 실제 장비의 프레임 지연과 카메라 입력 누적은 별도 검증 항목이다.

## Fire360 전후 비교

측정 입력은 IFSI4의 300–539번 프레임과 IFSI8의 90–329번 프레임이다. 각각 240프레임이며 동일하게 저장된 TEED 확률·원본 영상·OSD 마스크를 두 경로에 입력했다. 전체 영상 출력과 이 표의 측정 범위는 구분한다.

| 지표 | IFSI4 | IFSI8 |
|---|---:|---:|
| 움직임 정렬 후 경계 변화율, 기존 → 수정 | 0.13567 → 0.13206 | 0.14628 → 0.14278 |
| 경계 변화율 상대 감소 | 2.66% | 2.40% |
| 초록 선 밝기·위치 변화 지표 상대 감소 | 3.58% | 3.18% |
| 기존 경계 2 모델 픽셀 근방 보존 | 99.52% | 99.62% |
| 표시 경계 픽셀 수, 기존 대비 | 101.10% | 100.90% |
| 작은 성분 개수의 프레임별 변동, 기존 → 수정 | 2.021 → 1.967 | 2.000 → 1.992 |

실제 영상 전체의 변화량 감소는 작다. 움직이는 사람, 가림, 불·연기의 변화와 TEED 연결 구조 변화가 계속 남는다. 전체 경계 변화율은 순수한 오류나 깜빡임 정답률이 아니다. 선을 대폭 제거해서 얻은 결과도 아니다. 작은 성분의 변동은 IFSI8에서 거의 변하지 않았다.

합성 정적 카메라 이동 검사에서는 출력 위치 증분의 표준편차가 기존 0.4917 모델 픽셀에서 0.3114로 36.68% 줄었다. 이 수치를 실제 Fire360 전체 영상의 개선율로 해석하면 안 된다. 독립 움직임, 새 경계, 소멸, 단절, OSD 제외는 별도 합성 검사로 확인했다.

윤곽 단계만 분리한 첫 시도는 실제 영상 변화율을 1.28–2.02% 증가시켜 채택하지 않았다. 최종 방식은 정적 영역의 확률 안정화와 윤곽 위치 안정화를 함께 적용한다. 비교 기록은 `experiments/teed_ui/motion_split/probe_v2/`, 기각한 첫 시도는 `probe_v1/`에 보관한다.

## 처리 속도

Intel Core Ultra 7 258V, Windows, CPU 전용 PyTorch에서 동일 클립의 새 TEED 추론을 포함해 비교했다. 각 조건은 20프레임 준비 후 120프레임 측정, 라이브러리 4스레드·디코더 1스레드다. 동시 영상 변환 없이 측정했다.

| 입력 | 기존 | 분리 적용 | 분리 적용 지연 p95 |
|---|---:|---:|---:|
| fire360_ifsi10 | 2.75 fps | 2.33 fps | 541.9 ms |
| fire360_ifsi8 | 3.77 fps | 3.46 fps | 368.2 ms |

4K 파일 디코딩 → TEED 320×256 → HUD 720×405를 순차 측정했다. 화면 출력·인코딩·실제 카메라 대기열은 포함하지 않는다. 15/30fps 실시간을 만족하지 않으며 Jetson/실제 AR 장비 측정도 아니다. 녹화된 비교본은 원본 시간축 29.97fps로 재생된다.

근거: `experiments/teed_ui/motion_split/runtime/benchmark.json`.

## 전체 영상 재생성

```sh
python experiments/teed_ui/run_motion_render.py --numbers 4 5 6 7 8 9 10 --output full_replay --threads 1 --comparison
```

각 원본 프레임을 순서대로 새로 TEED 추론하고, 적용본과 직전 색상 보존 영상과의 좌우 비교본을 저장한다. 비교본은 왼쪽 기존·오른쪽 수정이다. 오디오는 포함하지 않으며 출력 아래 한 행은 인코더 크기에 맞춘 검은 여백이다.

Windows에서 진행 기록 파일을 읽는 순간 원자적 파일 교체가 잠깐 거부될 수 있어, 실행 래퍼는 `PermissionError`만 최대 20회 재시도하고 지속 실패는 그대로 보고한다. 모델·영상 처리 예외는 숨기지 않는다. 이번 실행 중 IFSI6의 첫 변환이 해당 잠금으로 중단되어, 미완성 파일을 `full_v1/failed_io/`에 보관하고 전체 구간을 다시 처리했다.

전체 좌우 비교본의 왼쪽은 이전에 저장한 VP8 영상을 불러오므로 재압축 차이가 있을 수 있다. 위 정량 비교는 이 파일의 픽셀 차이를 사용하지 않고, 동일한 원본·TEED 확률에서 두 경로를 직접 렌더링해 계산했다.

## 전체 출력 및 최종 검증

로컬 생성 목록 `experiments/teed_ui/motion_split/full_v1/README.md`에서 IFSI4–10 영상을 열 수 있다. 총 12,074프레임, 402.87초다. 적용본 7개와 비교본 7개를 끝까지 디코딩했고 프레임 수·시간축·크기·fps·파일 체크섬을 확인했다. 렌더링에 사용한 생산 코드와 최종 회귀 검사 코드가 동일한지도 해시로 확인했다. 이 README와 영상·검증 JSON은 GitHub 배포 대상이 아니다.

최종 회귀 계약 119개, 실제 CLI 4가지 조건(기존·분리 활성화·legacy 우선·루프 재시작), Ruff와 Basedpyright를 통과했다. 독립 코드 검토도 승인되었다. 각 영상의 대표 프레임과 연속 프레임 묶음에서 정렬·고온 색상·빨간 외곽선 보존을 확인했다. 모든 프레임을 사람이 실시간 재생하여 관찰한 것은 아니며, 장시간 잔상이나 분리 정확도의 실환경 보증은 아니다.

주요 구현 파일은 `edge/orin/motion_registration.py`, `temporal_edges.py`, `contour_tracker.py`, `hud.py`, `run_pipeline.py`다. 새 모델이나 의존성을 추가하지 않았다. 검증 근거는 `experiments/teed_ui/motion_split/final_regressions.json`, `pipeline_checks/final_verification.json`, `review.json`, `full_v1/verification.json`, `full_v1/visual_inspection.json`에 보관한다.
