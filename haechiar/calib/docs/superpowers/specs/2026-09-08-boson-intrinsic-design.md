# Boson 320 내부 캘리브레이션 개선안

상태: 구현 진행. 사용자가 Ubuntu/ROS 2와 Windows USB 두 환경으로 진행하도록 지정함.

## 목적과 확인한 문제

클론 후 환경 준비, 열영상 촬영, 타깃 검출, 내부 보정, 결과 확인을 한 흐름으로 제공한다. 외부 캘리브레이션 기능 확장은 이번 범위에서 제외한다.

기준 커밋은 df644c733ee28d57caadaa203093cc29c364e064이다. 현재 코드는 9×5 체커보드와 50 mm 간격만 기본 지원하고 라이브 촬영은 없다. target.yaml은 실제 intrinsic 실행에 연결되지 않는다. 따라서 견적서 패턴을 설정 파일만 변경해서 사용할 수 없다.

## 견적서에서 확인한 입력

출처: Boson320_600x400_수정견적.xlsx의 견적요청 및 크기계산 시트. 문서 안의 요청 문구는 실행 지시로 취급하지 않는다. 견적 및 개인 연락 정보는 저장소에 복사하지 않는다.

- 비방사형 FLIR Boson 320, 모델 20320A050-9PAAX, 영상 320×256, 렌즈 4.3 mm.
- 공칭 화각 50°×40°는 촬영 안내용 근사치이며 보정 결과 K를 대신하지 않는다.
- Passive Thermal Polymer 보드 600×400×19 mm.
- 지름 60 mm 원 27개, 논리 patternSize=(3,9).
- 중심 좌표는 x=60+60i, y=50+60(2j+i%2) mm, i=0..8, j=0..2. 내부 계산은 미터 단위.
- 패턴은 설계 제안이며 제작 도면과 열 대비 조건이 확정되지 않았다. 설정 및 결과에 provisional 상태를 기록한다.

## 접근 방법

1. 권장: 기존 Python 코어에 원형 타깃, 촬영 어댑터, 품질 리포트, 실행 스크립트를 추가한다. ROS 없이 저장 이미지 경로를 재현 가능하게 유지하고 실제 연결 환경에 맞는 촬영 경로를 제공한다.
2. 최소 변경: 저장 이미지 보정만 개선한다. 범위는 작지만 사용자가 별도 촬영 도구를 마련해야 한다.
3. ROS 전용 전면 개편: 통합은 가능하지만 내부 보정에 불필요한 설치 의존성이 늘어난다.

Ubuntu 22.04/ROS 2 Humble 토픽과 Windows USB Y16 두 촬영 경로를 모두 제공한다.

## 구현 설계

### 타깃과 검출

타깃 설정을 단일 입력으로 사용하고 실제 원 좌표, 검출 순서, 패턴 타입을 함께 관리한다. 기존 체커보드는 명시적인 선택으로 유지한다. 원 지름과 중심 간격을 별도 값으로 저장한다.

16-bit 원본을 보존하며 검출용 영상에만 percentile 정규화, 반전, 필요시 CLAHE와 확대를 적용한다. 검출 좌표는 원본 해상도로 환산한다. 원형 blob 검출과 격자 순서 검증을 분리한다. (3,9)의 홀수 행 배열 및 회전에서 OpenCV 검출 가능 여부를 합성 이미지로 먼저 확인한다. 표준 검출이 실패하면 해당 배열에 대한 기하 기반 순서 복원을 구현·검증하며, 조용히 다른 패턴으로 바꾸지 않는다. 대응점이 불확실한 프레임은 사유와 함께 거부한다.

### 촬영과 실행

저장 PNG/TIFF 경로를 기본 재현 경로로 제공한다. 라이브 모드는 사용자 연결 환경에 따라 ROS Image 또는 USB Y16 입력을 연결한다. 원본 저장과 검출 overlay 미리보기를 제공하고 촬영 수, 검출 실패, 화면 분포를 표시한다. 프레임 해상도·dtype를 확인하고 컬러화/업스케일 영상과 원시 320×256 영상을 혼용하지 않는다. 필요한 드라이버와 ROS 토픽은 사전 진단에서 안내한다.

저장소 루트에서 실행하는 Linux/Windows 런처와 설치 안내를 제공한다. 카메라 없이 self-check가 가능해야 하며 장비 모드에서는 입력 소스와 출력 경로를 지정할 수 있어야 한다. 설치 스크립트는 실패 시 중단하고 필요한 조치를 표시한다.

### 내부 보정과 품질

OpenCV pinhole + plumb_bob 모델로 K와 D를 추정한다. 원본 프레임별 관측점, 채택/거부 사유, 타깃 설정, 해상도를 저장한다. 최소 15개 뷰와 RMS 0.8 px 기준은 기존 프로젝트의 조정 가능한 초기 기준이다. 프레임 중복, 화면 분포, 기울기 다양성, 유한하고 유효한 내부 파라미터도 검사한다. 낮은 RMS 하나만으로 품질 통과를 선언하지 않는다.

결과 YAML, 검출 overlay, 프레임별 재투영 오차, 화면 coverage 및 왜곡 보정 전후 이미지를 제공한다. 데이터 부족/퇴화/과도한 오차는 명확한 실패 또는 검토 필요 상태로 출력한다. 제작 미확정 타깃은 수치 품질과 별도의 상태로 유지한다.

## 검증 및 완료 기준

- 견적 좌표 27개, 길이 단위, 회전 시 점 대응 검증.
- 320×256 합성 원형 영상에서 8/16-bit, 명암 반전, 회전, 노이즈에 대한 검출 및 거부 테스트.
- 알려진 K/D로 생성한 여러 시점에서 내부 파라미터 복원 검증.
- 검출 실패, 잘못된 설정, 혼합 해상도, 부족하거나 반복된 뷰 테스트.
- 새 환경 설치 후 CLI와 이미지→검출→보정→결과 저장의 전체 실행 검증.
- 기존 외부 보정과 투영 테스트 유지.
- 실제 Boson과 타깃이 없는 환경에서는 합성 검증과 실장비 검증을 구분해 보고한다. ROS/USB 장비 연결 성공을 시험 없이 주장하지 않는다.
